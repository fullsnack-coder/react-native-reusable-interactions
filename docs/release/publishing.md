# Publishing runbook — immutable beta and future releases

Iteration 7.2 published the explicitly approved 0.1.0-beta.1 archive to npm after owner 2FA. Do not rerun publication, rebuild/replace that archive or reuse this version. The sequence below is for a future separately approved release only. Git tags, GitHub Releases, pushes, deployments, store uploads and account modifications are not authorized by this runbook.

1. Owner has confirmed the existing MIT license and package identity; reporting uses Issues with private follow-up for sensitive details. Before a future release, establish/test the actual approved repository Issues location and approve the release gates. Evaluate known defects separately from unverified behavior. The maintainer explicitly deferred complete manual readers for this beta: Deferred by maintainer for beta — manual screen-reader validation pending. Keep later reader testing recorded; resolve known critical usability defects before release. Verify npm permissions/account locally, never put tokens in repository files. npm whoami must match the personal scope or a verified organization role.
2. Recheck exact public name/version against registry.npmjs.org with the appropriate scope registry override if local config routes elsewhere. A404 lookup is not legal clearance or reservation. Do not invent repository/homepage/contact metadata. Approve those actual links separately when they exist.
3. In a clean library checkout use Node 24.21.0, npm ci, npm run typecheck, npm run lint, npm run format:check, npm test, npm run build, npm run package:verify, npm run pack:check. Inspect lifecycle scripts first. prepack only runs npm run build; no prepare/postpack/prepublishOnly publishing hook. npm pack creates the reviewed candidate; keep its SHA256/SHA512 and file list. Confirm0.1.0-beta.1 metadata/lock, beta tag and public access.
4. Install that exact artifact in a fresh independent Community CLI consumer with direct documented peers; compile/typecheck and build/run Android/iOS, including all public imports and root host. Record artifact identity and real outcomes. A dry-run pack does not replace this gate. If content changes, rebuild/repack/revalidate; never overwrite a published version.
5. Final owner approval checkpoint: approve the exact candidate bytes, name/version, license, security/governance, automated gates, native/device evidence, the explicit beta reader deferral, known defects and limitations and intended beta dist-tag. Reconfirm authentication/permission/2FA through npm's local secure flow. Do not send credentials to an agent or store tokens here.
6. **Only in a separately authorized release**, publish the approved tarball using npm publish <approved-tarball> --access public --tag beta --registry=https://registry.npmjs.org (also pass the matching scoped registry option if required). This line is documentation, not an executed action. Do not use latest. Inspect scripts and npm's current prerelease behavior rather than invoking publish --dry-run blindly.
7. After authorized publication, verify registry metadata/integrity/tag and install @manueldev25/react-native-reusable-interactions@0.1.0-beta.1 in a fresh consumer. Publish release notes/docs/remote tags only under their separate owner authorizations. Public installation via @beta follows that tag; no-tag installation follows latest. A prerelease version and a beta tag are distinct and both intentionally specified.
8. Recovery: published versions cannot be overwritten. Stop promotion, disclose known defects, prepare a new beta/patch and consider an owner-authorized deprecation of the affected version. Removing/moving a tag does not remove already installed content. Unpublish eligibility is limited by npm policy and must not be assumed. Never automatically deprecate/unpublish or revert user data.

Hosted CI has not run because no remotes exist. Local checks are recorded separately. Existing showcase Release signing is for testing, not store distribution. No automatic publishing workflow is installed.
