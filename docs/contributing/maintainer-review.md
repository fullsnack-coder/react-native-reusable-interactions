# Maintainer review

The initial maintainer is the project owner. Review scope/usefulness, alternatives/dependencies, typed API and migration, gesture ownership, controlled requests, cancellation/unmount, callback safety, accessibility alternatives/focus, exact compatibility, package exports, meaningful regression tests and honest evidence. Verify public docs and journal, including failed experiments and missing measurements.

Keep review proportional. Prefer reproducible fixes to stylistic rewrites; do not promise arbitrary navigation/scroll/keyboard support. Classify Blocker/High/Medium/Low risks by impact and reachability. Check private-data/secrets exposure. Keep Implementation Complete, Physical Device Validated and Release Ready separate. Never promote Stable or publish based solely on test count. The owner approves license, identity, contact channels and final release; no publishing workflow or new credentials are introduced.
