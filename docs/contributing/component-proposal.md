# Component proposal template

Status: Proposed. Author/date: actual values only.

- Problem and intended use cases; overlap with existing interactions.
- Proposed TypeScript API and usage; controlled/uncontrolled ownership and callback semantics.
- Gesture/animation behavior, interruption, scroll conflicts, lifecycle and failure states.
- Android/iOS compatibility and dependencies; custom vs existing engine alternatives.
- Accessible non-drag alternative, roles/labels/states/focus, reduced motion, large text and touch targets.
- Meaningful automated tests and planned native/device/screen-reader evidence.
- Performance method and risks; no fabricated target/FPS claims.
- Public docs and five Engineering Journal records required.
- Unsupported scope, migration impact and acceptance criteria.

Do not implement until scope/review is agreed. Community proposals can extend beyond the initial six components.
