# InteractivePurchaseSheet implementation journal

Recorded 2026-11-09. Iteration 6. Development time not measured.

Reviewed four repository instructions, five previous components, installed skills, test conventions, prior native/performance evidence and cumulative release policy. Official Gorhom v5 docs, tagged 5.2.14 source, manifest, releases and npm size metadata were examined before selecting a custom bounded scope (ADR 0008). Peer ranges admit our stack; no incompatibility, native Gorhom compatibility pass or speed advantage is claimed. No Gorhom dependency was installed.

Implemented controlled Modal visibility/index, fraction geometry, release/velocity selection, generation-guarded springs, handle-only pan, independent internal ScrollView, scrollable footer, dismissal requests vs completion and guarded accessible actions. Measured header plus 48-point body floor improves constrained layout. A live OS motion preference snaps transitions. Body height follows visible sheet height on UI; this intentionally performs layout, not only GPU transforms. No per-frame React updates or shared framework.

Testing harness corrections: Jest each-array configurations need single-argument rows; Worklets callbacks must be explicitly controlled; semantic controller tests run the reduced-motion path rather than assuming an unadvanced spring has settled. Initial failed assertions left unmounted timers until harness cleanup was corrected. Tests do not establish native gesture smoothness. Existing App safe-area mock now includes useSafeAreaInsets for the new consumer composition; prior assertions are preserved.

Native Android real touch input exercised 1→2→3 snaps, body scrolling without sheet movement, scroll-top downward continuation without transfer, child buttons, canceled pan via Home, collapse and swipe down, backdrop and hardware Back, dynamic point removal, locked close/back/drag and horizontal content. First keyboard attempt used hardware input because the emulator hid the soft keyboard. Enabling soft input revealed Gboard handwriting UI; a bounded retry temporarily disabled handwriting, then restored both settings. The standard keyboard revealed an actual overlap/Back issue, separate from those environment limitations.

Native iOS keyboard initially obscured a focused standard TextInput. The public responder helper measures input in local content coordinates but compares against screen keyboard Y. Measuring the modal ScrollView origin and adding it to the reveal offset fixed the observed overlap; regression covers a nonzero origin and stale measurement after unmount. Genuine before/after screenshots retained; typing and native Done were observed after the fix.

After dynamic lock/unlock and rapid reopen, iOS exposed Close as a slider. Modern role props produced generic AX elements rather than solving it and were reverted. A direct pressable Text host corrected the role but exposed a nested inline button; unsupported Text onAccessibilityTap was rejected by installed strict types. Final close uses installed RNGH v3 Touchable, a distinct native button host, with no new dependency. Repeating the original sequence yielded one Close button plus an adjustable handle, and native accessible closing incremented dismissal exactly once. Regression preserves the native host choice. Underlying view recycling/trait contamination is an inference, not independently proven.

The bounded Modal navigation-translucency change did not resolve actual standard-IME overlap on Android 16. The prototype and failed evidence were retained instead of treating a successful text injection as keyboard validation. ADR 0009 supersedes Modal presentation with a scoped root PurchaseSheetHost. This wrapper renders one owner slot, blocks background touch/accessibility, removes the overlay after close/unmount, rejects simultaneous owners, and uses the main-root keyboard context. Existing dependencies/native configurations and previous components remain unchanged. All four caller safe-area insets now apply on both platforms. Android uses height KeyboardAvoidingView and Back prioritizes a visible keyboard. Regression tests cover host ownership, missing host, background isolation, close cleanup, safe-area insets and Back ordering. Revalidation of this final implementation is recorded in validation.md; prototype checks are not silently transferred.

Showcase uses only the packed public package, fictional carry-set content, controlled points, quantity controls, horizontal finishes, standard input, long-content/footer, dismissal lock, rapid requests and timed unmount. No payment/network logic or coupling to prior microinteractions. Public reference and text-only landing catalog added. Final checks, build artifacts and source preservation audit will be linked from validation.md.
